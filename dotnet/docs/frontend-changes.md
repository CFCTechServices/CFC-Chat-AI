# Frontend changes for the .NET migration

Track UI work required by `dotnet/docs/plan/internal-api/internal-api-remaining-endpoints-plan.md`. **Checklist only: none of these UI changes are implemented by this document.** Ship the matching backend and UI changes together; Python and .NET will not have identical contracts everywhere. Primary app paths are under `web/components/` and `web/js/`; legacy `web/app_legacy.jsx` / `web/app_legacy.js` should be updated only if still served, otherwise explicitly retire them. Confirm which upload utilities are actually loaded before changing them.

## Required for the agreed API decisions

- [ ] **Admin-only multipart uploads** — `web/components/admin/upload.jsx` sends video `fetch` and document `XMLHttpRequest` without auth. Add `Authorization: Bearer <access_token>` to both, including the bulk, EML and PDF flows, and disable/show a useful error when the admin session is unavailable or expired. For XHR, call `setRequestHeader` after `open`; leave the multipart `Content-Type` unset so the browser supplies the boundary. Apply the same rule to active `web/js/upload-single.js` and `web/js/upload-bulk.js`; bulk remains multiple authorized calls to `/api/files/upload`, **not** the excluded `/api/files/bulk`. Check legacy `web/app_legacy.jsx` and `web/app_legacy.js` (`/files/upload` is a different old path) before cutover. Display 401/403 and partial/503 failures, not "Ingested" simply because bytes transferred. Verify users without admin rights cannot access upload controls.
- [ ] **Upload result/validation handling** — `web/components/admin/upload.jsx` currently reads `data.supabase.warning`; `web/js/upload-single.js` and `web/js/upload-bulk.js` read `data.ingestion.sections_processed/chunks_processed`. Align with the finalized .NET success DTO (e.g. chunk/vector counts), remove dependence on Python's best-effort Storage mirror, and show a failure if original storage or ingestion fails. Keep client extension/size hints in sync with backend rules; these are UX hints, not security checks. Refresh the content list only after confirmed success.
- [ ] **Video uploads and artifacts** — `web/components/admin/upload.jsx` derives `slug` from filename and submits `model=small`. Normalize/validate the slug as the stable document ID and show an explicit conflict/validation error; do not offer unsupported Whisper model values. If `language` is offered, submit only Azure-supported locales. Use the returned `ok`, `slug`, `original_video_url`, `transcripts.{txt,srt,vtt}`, `summary_md` only after successful processing; these are **expiring signed URLs**, not permanent stored links. Re-request links when reopened/expired (backend refresh mechanism or repeat authorized lookup must exist), and handle 403/expired/404 without exposing Storage credentials. Test video playback/download and transcript links in any active or legacy UI (`web/app_legacy.jsx`).
- [ ] **Chat image signed links** — `web/js/chat-utils.js` currently turns `relevant_images[].path` into an `<img src="/api/chat/content/images/...">`; `web/components/chat-message.jsx` and `web/components/chat.jsx` render that directly, including images reconstructed from message history. Both `/api/chat/content/images/{path}` and `/content/images/{path}` will instead require a current-user bearer token and return `{url, expires_at}` (JSON). Resolve each image path with an authorized `fetch`, then set `<img src>`/modal image to the returned signed URL. Handle loading, 401/403, 404, expiry/retry and session change; do not cache signed URLs in persisted message metadata or log them. Preserve original paths for history reload and re-resolve when links expire. Encode path segments safely without allowing traversal. Update legacy `/content/images/...` use in `web/app_legacy.jsx` if that client is retained. Test images in new replies, history, modal and after URL expiration; an ordinary `<img>` cannot attach bearer headers.
- [ ] **Local staging stats, not cloud progress** — `web/components/admin/ingestion.jsx` currently labels the scan "Monitor AI content ingestion progress" and renders `processing`, `completed` and document status. Relabel it as **local staging files only**, with a note that direct .NET uploads might not appear and `processing: 0` is not live job progress. If `/api/admin/ingestion/stats` returns 503 because staging directories are absent, show "Local staging unavailable" (with retry) rather than zero counts or a false successful empty state. Keep existing `documents:[{name,size,status}]` display for configured directories.
- [ ] **Document actions** — `web/components/admin/content.jsx` already authenticates delete/replace. A missing document now returns 404: show "No longer found" and refresh the list, not a success notification. On partial/non-2xx delete or replace, keep the row visible, show the safe error/reconciliation hint and refresh before retry; never display "Replaced successfully" before confirmed completion. Replacement must preserve the requested `doc_id`; preflight or surface filename/type/ID mismatch to the user without assuming a new ID was created. The existing replacement picker only accepts `.doc,.docx`; align it with the supported backend types. Existing download URLs (`GET .../download`) are also short-lived: use them immediately and re-fetch on retry.
- [ ] **Account admin failures** — `web/components/admin/user.jsx` already authenticates deactivate, reactivate and permanent delete. Treat 404, invalid lifecycle transitions and partial failures as errors; refresh user state before retry and do not optimistically mark users active/deleted. Prevent self/superuser actions in UI for clarity (API enforcement remains authoritative). If the API exposes a safe operation/reference ID, display it for operator support; never show provider exception details.
- [ ] **Profile editing only after security gate** — `web/components/settings.jsx` already calls `PATCH /api/profile/me` with a bearer token. Keep editing disabled/unavailable until the profile ACL/RLS/signup gate in `dotnet/docs/plan/supabase-profile-self-service-security.md` is closed and the .NET write routes are enabled. Check empty/cleared fields and validation errors against the eventual PATCH semantics. Audit any signup/profile completion client before using `POST /api/profile/complete`; it is an alias for an existing authenticated profile, not a create-profile route.
- [ ] **Operator-only local ingest** — `POST /api/ingest/document` is retained for admin operators; no end-user UI is required. If an operator control is added, require admin auth, accept only a staged filename, and handle missing staging root and non-2xx failures. Do not let a browser provide an arbitrary local server path.

## Other cutover checks (existing routes, not newly planned UI features)

- [ ] Verify active client handling of the existing .NET divergences in `dotnet/docs/plan/internal-api/internal-api-endpoints-implementation.md`: validation is 400 instead of Python 422; list ceilings can return 413; vector stats require a current user; provider-backed routes may be absent (404) when configuration is incomplete. Do not treat an error as an empty successful list.
- [ ] Run browser smoke tests for admin uploads (including XHR progress), video links, chat images/history/modals, admin document/user operations, local stats and profile settings against disposable non-production providers. Confirm authenticated CORS/proxy behavior and Storage signed-link access in the target deployment; do not put signed URLs or access tokens in client analytics/error logs.
