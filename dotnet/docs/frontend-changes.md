# Frontend changes for the .NET migration

Status of the checked-in UI for the .NET migration. Checked boxes indicate code changes, **not** browser or provider acceptance. Ship matching backend, routing and UI changes together; Python and .NET do not have identical contracts everywhere. Primary app paths are under `web/components/` and `web/js/`; audit legacy pages and upload utilities only if they are served. See the [routing and hosting plan](plan/routing-and-hosting.md) and [cutover checklist](plan/internal-api-cutover.md).

## Required for the agreed API decisions

- [x] **Admin-only document multipart uploads** — the active `web/components/admin/upload.jsx` sends the current bearer token after XHR `open`, leaves multipart Content-Type to the browser, handles missing/expired sessions and errors, and sends bulk as sequential single-file requests. Video upload is unavailable. The checked-in `web/index.html` loads this component and `main.jsx`, not `web/js/upload-single.js`, `web/js/upload-bulk.js` or the legacy apps; reassess if other pages are deployed. Browser/proxy smoke testing remains outstanding.
- [x] **Document upload result handling** — active upload flows require the .NET document ID and counts before showing success and display non-2xx failures. The server enforces the size and type rules. The active UI's Python upload contract is no longer compatible; coordinate routing before deployment.
- [ ] **Video uploads and artifacts** — video upload is disabled in the active UI for .NET; a future video implementation must normalize/validate the slug as the stable document ID and show an explicit conflict/validation error; do not offer unsupported Whisper model values. If `language` is offered, submit only Azure-supported locales. Use the returned `ok`, `slug`, `original_video_url`, `transcripts.{txt,srt,vtt}`, `summary_md` only after successful processing; these are **expiring signed URLs**, not permanent stored links. Re-request links when reopened/expired (backend refresh mechanism or repeat authorized lookup must exist), and handle 403/expired/404 without exposing Storage credentials. Test video playback/download and transcript links in any active or legacy UI (`web/app_legacy.jsx`).
- [x] **Chat image signed links** — `web/components/chat-message.jsx` resolves `/api/chat/content/images/...` with a bearer token, accepts signed-link JSON or Python image bytes, and retries once on image load failure. Verify new replies, history, modal, expiry and session changes in a browser with private Storage; audit the legacy `/content/images/...` client if retained.
- [x] **Local staging stats** — `web/components/admin/ingestion.jsx` labels the metric local staging and displays a 503 as unavailable with retry. The component is not currently mounted in the active admin UI. If enabled, browser-test configured and missing directories; this is not cloud ingestion progress.
- [x] **Document actions** — `web/components/admin/content.jsx` authenticates delete and replacement, checks confirmed responses and displays partial-failure references. Browser smoke tests and same-origin routing remain outstanding. The Python delete route can report false success; do not use this UI against it. A 404 does not prove cleanup after an earlier failure. Download URLs are short-lived; re-fetch on retry.
- [x] **Account admin failures** — `web/components/admin/user.jsx` authenticates lifecycle operations, checks confirmed outcomes and displays failure references. Verify invalid states, self/superuser behavior, retries and lost responses in the browser; API enforcement remains authoritative. Lifecycle and permanent deletion remain separately gated.
- [ ] **Profile editing only after security gate** — `web/components/settings.jsx` calls `PATCH /api/profile/me` with a bearer token and currently presents editing; the default-off API flag makes the .NET route unavailable but does not hide the UI. Disable the affordance or provide an explicit unavailable state until enabled-route tests and the [profile security gate](plan/supabase-profile-self-service-security.md) pass. Check empty/cleared fields and validation errors. Audit signup/profile completion before using `POST /api/profile/complete`; it updates an existing authenticated profile, not creates one.
- [x] **Operator-only local ingest** — `POST /api/ingest/document` is implemented as an admin-only route constrained to a configured staging root, with no UI. The separate unauthenticated `/api/ingest/dev` and `DELETE /api/ingest/dev/{docId}` are opt-in, Development/direct-loopback-only and must never be exposed or proxied.

## Other cutover checks (existing routes, not newly planned UI features)

- [ ] Verify active client handling of .NET divergences: validation is 400 instead of Python 422; list ceilings can return 413; vector stats require a current user; provider-backed routes may be absent (404) when configuration is incomplete. Do not treat an error as an empty successful list. The archived [implementation record](complete/internal-api/internal-api-endpoints-implementation.md) predates the remaining-endpoints delivery.
- [ ] Run browser smoke tests for admin uploads (including XHR progress), video links, chat images/history/modals, admin document/user operations, local stats and profile settings against disposable non-production providers. Confirm authenticated CORS/proxy behavior and Storage signed-link access in the target deployment; do not put signed URLs or access tokens in client analytics/error logs.
