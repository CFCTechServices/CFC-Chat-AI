# Remaining internal API endpoints — implementation plan

**Historical plan:** All eight in-scope routes have since been implemented; profile writes map only when `Api:EnableProfileWrites` is enabled, and remain gated on tests and database security. See the [delivery notes](internal-api-remaining-endpoints-delivery.md) for the first six routes and the current [cutover checklist](../../plan/internal-api-cutover.md). The baseline and proposed steps below describe the earlier plan, not current status or cutover approval.

## Baseline and boundary

This is the follow-on to `internal-api-endpoints.md` and `internal-api-endpoints-implementation.md`, updated against the merged `migration/dotnet` code. It tracks **eight remaining method/path pairs**, including the retained operator route. Video upload is deferred and is not part of this delivery. Existing routes still require provider-backed and browser validation; implementation is not a cutover approval.

| Workstream | Remaining, not mapped | Dependency / decision |
|---|---|---|
| Profile | `PATCH /api/profile/me`, `POST /api/profile/complete` | Database self-service security gate |
| Account admin | `POST /api/admin/users/{user_id}/deactivate`, `POST /api/admin/users/{user_id}/reactivate`, `DELETE /api/admin/users/{user_id}` | Auth/profile cross-provider reconciliation |
| Local admin | `GET /api/admin/ingestion/stats` | Local-staging-only metric; unavailable when staging is not configured |
| Document admin | `PUT /api/admin/documents/{doc_id}/replace` | Preserve document ID; report partial failures |
| Operator | `POST /api/ingest/document` | Admin-only, constrained staging root |

**Already mapped:** admin document upload (`POST /api/files/upload`), admin document deletion (`DELETE /api/admin/documents/{docId}`), and authenticated image aliases (`GET /api/chat/content/images/{path}` and `GET /content/images/{path}`). Document upload and deletion require configured Supabase and Pinecone; image resolution requires Supabase. See [upload](../../complete/document-upload/document-upload-changes.md), [deletion](../../complete/document-deletion/document-deletion-changes.md), and [image remediation](../../complete/document-upload-remediation/README.md). The active UI uses the new upload/delete and signed-image contracts. Existing health, auth/config, invitation, profile read, sessions, chat/feedback, vector stats, and admin reads/settings are also mapped where configured.

**Deferred:** `POST /api/videos/upload` and its UI/artifact work. The active upload UI already rejects video; keep it unavailable rather than routing it to document ingestion. Document deletion currently rejects video and unknown source types. Do not port unmounted `transcripts.py`, bulk/search/ask/recommendations routes excluded by `internal-api-endpoints.md`, or the SPA fallback under this endpoint plan. Provider-backed routes must not return mock successes when configuration is absent. Follow existing snake_case JSON except explicitly agreed compatibility changes.

## Agreed product decisions (do not reopen implicitly)

- **Document uploads and local-file ingest:** admin-only, except the separately gated local development routes. The active document upload UI already attaches bearer tokens; audit legacy upload utilities only if they are deployed. Do not preserve Python's public upload behavior.
- **Images:** the mapped aliases return short-lived signed URLs to active, authenticated users rather than Python's image bytes. The active chat UI resolves them with a bearer token; verify private-bucket access and browser behavior. Assess document-level access if the knowledge base is not shared by all active users. Never place service-role credentials in URLs or logs.
- **Video:** deferred for now. Future work should preserve the slug as document ID, store original and TXT/SRT/VTT/markdown artifacts, use Azure Speech with documented options, and return refreshable short-lived signed URLs. These are not current delivery requirements.
- **Replacement:** preserve the requested document ID; reject incompatible ID/type before deletion and report partial multi-provider failures. **Existing delete:** 404 means metadata is absent, not proof that all provider data was removed. Durable recovery and concurrency fencing were waived for the current development implementation; do not claim they are implemented.
- **Ingestion stats (interim simple choice):** retain the Python-style local directory scan *only* as a local staging metric. Label it as such in `web/components/admin/ingestion.jsx`; never call it cloud ingestion progress. If staging paths are absent/unconfigured, return a clear unavailable response (503), not misleading zero totals. Configured empty directories may return zero. Revisit a durable job metric later.
- **`POST /api/ingest/document`:** keep it, admin-only, restricted to a configured staging root.

## Preconditions shared by these routes

1. Keep the existing admin/current-user policies and align active clients with each new contract; do not make admin routes public for Python compatibility. The .NET host does not currently serve the UI: static hosting, SPA fallback and same-origin routing/proxy are separate prerequisites for browser testing, not endpoint implementations.
2. `Program.cs` already registers document processing and handling when Supabase and Pinecone/embedding configuration is present; video processing is not needed for document ingestion. Reuse configured upload limits and accepted document types for replacement and staged ingest; bound work, cancellation and staging paths. LibreOffice may be required for legacy `.doc` files. Do not enable video processing as part of this plan.
3. `IDocumentHandler` owns ingestion/deletion. Writes across images, chunks, vectors and original Storage are not transactional. Delete removes vectors, the document Storage tree, then rows; missing metadata is 404 and does not trigger blind cleanup. Existing upload duplicate preflight is not a lock. The current development implementation has no durable recovery or fencing; avoid concurrent same-ID operations and follow the linked manual reconciliation notes. Replacement must define and test its own partial-failure/recovery behavior before it is exposed; do not imply that existing delete provides guarantees it does not have.
4. For every new route, add fake-based contract/authorization tests and disposable non-production provider tests. Test missing configuration, inactive/deleted principals, invalid identifiers, partial provider failures and cancellation. Release gates include `dotnet/docs/complete/internal-api/supabase-completion-remaining-plan.md` and UI smoke/contract comparison against Python where applicable. Avoid returning 200 for partially completed destructive operations.

## Endpoint work

### 1. Self-profile writes (blocked by database gate)

- **`PATCH /api/profile/me`** — Current-user policy and caller's token/ID to `IUserProfileRepository.UpdateCurrentAsync`; accept only `full_name` and `avatar_url`, require at least one provided field, distinguish omitted from null according to an agreed contract, validate lengths/URL and reject privilege fields/unknown fields. Return the updated `ProfileResponse` shape (`id`, `email`, `full_name`, `avatar_url`, `role`, `status`, `created_at`); return 404 if profile no longer exists/visible, never allow changing identity/role/status. Tests: allowed edit, empty/unknown/mixed privileged input, other-user ID spoofing, missing/disabled profile, caller-token RLS, cancellation. **Do not map until** `dotnet/docs/plan/supabase-profile-self-service-security.md` has an applied, reviewed ACL/RLS/signup migration and direct PostgREST negative tests (including anon and mixed protected-field updates). The .NET DTO is not a security boundary against direct Supabase clients.
- **`POST /api/profile/complete`** — Alias of the same validated write logic and response; do not silently create a profile or bypass the security gate. Verify signup profile creation is functional and safe before exposing. Test response/validation equivalence to PATCH, including first-login and already-complete cases; neither path may bypass the current-user policy.

### 2. Admin account lifecycle

All three use the existing `/api/admin` admin policy, validate GUID target IDs, read the target via `IAdminProfileRepository.GetByIdAsync`, and block self-target and superuser-target actions. `IAdminProfileRepository.UpdateAccountStateAsync` enforces **no** lifecycle policy; implement it in the API/application workflow. `IAdminIdentityGateway` is privileged; keep its results and errors sanitized. Choose a durable audit/reconciliation method before enabling these operations, since Supabase Auth and profile updates cannot share a transaction. Re-read/conditionally update state to guard concurrent admins and status changes (add a conditional repository method if necessary).

- **`POST /api/admin/users/{user_id}/deactivate`** — Optional `{reason}` request; bound/sanitize reason and keep it out of ordinary logs if sensitive. Reject absent, inactive or deleted target. Retrieve Auth email if required for the legacy response; decide whether missing Auth account is conflict vs recoverable partial failure, not `"unknown"` success. Ban via `SetBannedAsync(id, true)`, revoke sessions via `RevokeSessionsAsync`, then set profile `status=inactive`, `deleted_at=UTC now`, `deleted_by=admin ID`. JWT revocation alone may not immediately invalidate existing access tokens; current-user profile check must block them. Choose/report policy for any Auth failure: no silent Python-style continue-and-success. Preserve response keys `message`, `user_id`, `email`, `status`, `deleted_at`. Test failure at each step and retry from each partial state; make deactivation safe to resume.
- **`POST /api/admin/users/{user_id}/reactivate`** — Only eligible inactive targets, not permanently deleted accounts; validate Auth user exists, unban via `SetBannedAsync(id, false)` and restore profile `status=active`, `deleted_at=null`, `deleted_by=null` (legacy `restored_at` UTC response). Python deactivation itself sets `deleted_at`, so that field alone cannot distinguish an inactive account from another deletion state; verify the target schema and agree on an unambiguous lifecycle rule before implementation. Carefully sequence to avoid leaving a profile active while Auth remains banned, or Auth enabled while profile is inactive; report/reconcile either partial outcome. Test inactive accounts with deactivation metadata, already-active/deleted, Auth missing, unban failure, profile failure and retry.
- **`DELETE /api/admin/users/{user_id}`** — Irreversible: verify target role/state and identity/email, delete invitations by email via `IInvitationRepository.DeleteByEmailAsync`, then `IAdminIdentityGateway.DeleteUserAsync`. Check actual Auth → profile/session/message FK cascades and invitation/feedback `SET NULL` behavior in a disposable project, rather than relying on Python's comments. Decide whether invitation deletion failure blocks Auth deletion and how to reconcile a succeeded invitation deletion followed by failed Auth deletion. Return `message`, `user_id`, `email`, `permanently_deleted: true` **only** after confirmed deletion; prevent races with other admin changes. Tests: no target, self/superuser, Auth not found, invitation failure, Auth failure, retry after partial deletion, and real cascade verification.

### 3. Local admin ingestion status

- **`GET /api/admin/ingestion/stats`** — Admin policy; Python `app/api/endpoints/admin/ingestion.py` recursively scans `DOCUMENTS_DIR` for `.pdf/.doc/.docx/.txt/.md`, compares filename stems to subdirectories of `PROCESSED_DIR/content_repository`, and returns `{total_documents, processing:0, completed, documents:[{name,size,status}]}` with `pending`/`ingested`. Implement a bounded read-only scanner with configured paths, safe missing-dir semantics, IO error behavior, deterministic ordering and no path leakage. This is **not** a Pinecone/Supabase completion metric; current .NET ingest stages in temp and deletes that staging file, so Python's rule may always return empty or stale results. For now use configured local staging/processed directories and a bounded legacy-compatible scan; mark the UI (`web/components/admin/ingestion.jsx`) explicitly as **local staging**, not cloud ingestion progress. Return 503 if paths are not configured or no longer exist, with a safe error response; return zero only when configured directories exist and contain no matching documents. Document that uploads handled directly by .NET do not necessarily appear here; a durable job-status metric is future work. Test extension filtering, recursive files, duplicate stems, missing/denied directories, scan limits and UI interpretation.

### 4. Admin document replacement

Document upload and deletion are already mapped; they are not remaining endpoint implementation work. Their live provider and browser verification is still outstanding, including image/original cleanup and independent vector deletion checks. The current delete route accepts known document metadata only and does not clean up missing-metadata or video records.

- **`PUT /api/admin/documents/{doc_id}/replace`** — Validate target exists via `IChunkRepository.GetDocumentMetadataAsync`, admin policy, multipart `file`, same upload constraints. Python writes a local file, purges then calls the ingest endpoint (which derives the new ID from filename): it does **not** guarantee ID preservation. Extend the handler with a stable-ID/source-name replacement operation (or validate an exact ID match for a simpler first version); always preserve the requested ID and reject incompatible source type/file before deleting anything. Define same-key original overwrite explicitly in tests; reject video replacements for now, and do not silently change ID or source type. Prefer stage/process new content before destructive delete; otherwise add a durable per-document recovery record and return an explicit partial-failure error if delete succeeded but ingest failed. Never call the HTTP upload handler internally. Success `{success:true,message,ingestion:...}` only after all providers succeed; test missing doc, ID/type mismatch, validation before delete, failure at each delete/ingest stage, concurrent replace vs delete/upload, unchanged downloadable original on failed replace where promised.

### Existing image aliases: verification, not implementation

`GET /api/chat/content/images/{path}` and `GET /content/images/{path}` are mapped to the current-user-protected signed-URL resolver. Supported embedded DOCX PNG/JPEG/GIF images are extracted, stored and associated with chunks; the active chat UI resolves links for new answers and history. See [document upload remediation](../../complete/document-upload-remediation/README.md) for limitations and path/MIME rules. Legacy local `images/{filename}` paths are not migrated and return 404. Test private-bucket access, new and reopened chat images, expired links and deletion against disposable providers; offline tests do not establish live behavior.

## Retained operator route

- **`POST /api/ingest/document`** — Mounted in Python but hidden and now explicitly retained as an admin-only operator route. Accept only a validated filename under a configured staging root (real-path containment, symlink/traversal protections), call `IDocumentHandler.IngestAsync`, return a documented `IngestResponse` mapping and test unknown files, malformed paths and provider failures. If the staging root is absent, return a clear unavailable error rather than searching arbitrary filesystem paths. Do not expose Python's local filesystem read to unauthenticated callers. `POST /api/ingest/bulk` remains out of scope.

## Delivery and acceptance sequence

1. Implement the local staging stats and admin-only staged-file ingest routes with configured roots, bounded scanning/path validation and tests. `web/components/admin/ingestion.jsx` is not currently loaded by `web/index.html` or the active admin page; if the stats UI is re-enabled, label it local staging and handle 503 explicitly.
2. Implement admin account lifecycle routes with explicit state transitions, cross-provider partial-failure/reconciliation decisions, concurrency and UI error handling. Finish disposable Auth/profile/FK checks.
3. Define replacement's ID, overwrite and recovery behavior; implement the route and restore its UI only after those decisions and failure tests. Document that video replacement remains deferred.
4. Finish the profile ACL/RLS/signup gate and direct PostgREST negative tests, then implement both profile writes and enable the matching UI. Do not enable self-profile writes while the gate is open.
5. Compare the eight remaining contracts with Python where applicable, recording deliberate differences. Run fake-based tests and disposable-provider/browser smoke tests for the new routes **and** already-mapped upload/delete/image flows. Verify frontend hosting/routing separately; do not proxy development-only ingest/delete endpoints. Video upload is not a prerequisite for this scope.
6. Route traffic only after deployment-specific configuration/permissions, security-owner approval, backpressure/load tests and appropriate operator repair procedures. Until then keep Python routing for missing paths or explicitly disable those features; do not use a green .NET unit-test run as a cutover signal.
