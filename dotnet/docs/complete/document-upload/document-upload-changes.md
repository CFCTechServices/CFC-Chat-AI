# Document upload endpoints: PR notes

## Changes

- Added `POST /api/files/upload`, protected by the existing active admin/superuser policy, and `POST /api/ingest/dev`, registered only with `Api:EnableDevIngest=true` in Development. The latter additionally requires a direct IPv4/IPv6 loopback connection and is unauthenticated. Both are absent without complete Supabase and Pinecone configuration.
- Both accept one multipart `file` in `.pdf`, `.docx`, `.doc`, `.txt`, `.md`, or `.eml`; no videos or server paths. Filenames and derived IDs are validated, actual file length is checked, and the default document limit is 50 MiB. The HTTP request allowance includes 1 MiB for multipart overhead. Configure `Document__MaxUploadBytes`; the same value is used by the handler and processor. HTTP form parsing may spool to temporary files, and the handler stages and cleans its own file.
- Responses use `document_id`, `source_name`, `source_type`, `chunk_count`, `vector_count` only after all three writes succeed. Errors are sanitized. The handler attempts compensation for chunk/vector writes; failure to compensate is a 500 and requires reconciliation. Storage and other writes are not transactional, and a failed storage request may still have had side effects.
- The authenticated route checks the processor's exact normalized filename ID for existing chunks and returns 409. The preflight is not atomic; concurrent uploads can still collide. The dev route skips it entirely: repeated/colliding IDs can mix chunks and overwrite originals. Always use unique test filenames and never use dev ingest for replacement.
- Document handling now resolves without Azure Speech/video registration. A configured video processor is resolved only for video; a missing one fails explicitly. The HTTP routes remain document-only. The host passes `PINECONE_NAMESPACE` to the index adapter.
- The active `web/components/admin/upload.jsx` obtains a session bearer token for each single, sequential bulk, EML and PDF upload. It checks the .NET response before reporting success and makes video upload unavailable. `web/index.html` loads this UI; it does not load the separate `web/js/app.js` upload utilities or legacy apps. Recheck any separately deployed pages.

## Setup and operational limits

- `.doc` conversion requires LibreOffice: configure `Document__LibreOfficePath` if `soffice` is not on PATH. PDF extraction uses PdfPig embedded text; there is no OCR for image-only scans.
- Configure both providers, `Embedding__ModelPath`, `Embedding__VocabularyPath`, and the intended `PINECONE_NAMESPACE`. Nonempty settings only control route registration; they do not establish connectivity. Before live writes verify the **development** Supabase project and buckets, Pinecone index/namespace, and that the model and vocabulary match the index. Credentials stay server-side.
- The checked-in Python host serves `/ui/` and its own API; the .NET host does not serve the UI or configure browser CORS. No checked-in development routing has been verified to send the UI's relative `/api/files/upload` requests to .NET. Configure and verify a same-origin proxy or an explicitly allowed CORS setup before browser testing. The UI now expects the .NET upload contract and should not be deployed unchanged against Python. **Never proxy the dev ingest route**: even a local proxy could appear as loopback.
- Local curl: set `ASPNETCORE_ENVIRONMENT=Development` and `Api__EnableDevIngest=true`, bind only to loopback, and run `curl -F "file=@./unique-document.txt" http://127.0.0.1:5000/api/ingest/dev` (`curl.exe` in PowerShell). Keep the flag off on shared, containerized, remotely accessible and production hosts. Check HTTP status and response, not transfer completion.
