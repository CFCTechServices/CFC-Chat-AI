# Remaining internal API endpoints — implementation plan

## Baseline and boundary

This is the follow-on to `internal-api-endpoints.md` and `internal-api-endpoints-implementation.md`, checked against the current `dotnet/src/CFC.ChatAI.Api/Program.cs`, `Endpoints/InternalApiEndpoints.cs`, and `Endpoints/AdminReadEndpoints.cs`. **No endpoint below is currently mapped in .NET.** The existing health, auth/config, invitation, profile read, sessions, chat/message, feedback, vector stats, admin invite/users/role/settings, and admin document list/download routes are *not* new endpoint work here. Their outstanding cutover/security work remains in the implementation-status document and is a release dependency, not evidence of completion.

Scope is the remaining *retained and mounted* Python API, including the two image aliases: **12 required method/path pairs** (counting the two profile writes and two image aliases separately). A thirteenth, `POST /api/ingest/document`, is retained as an admin-only operator route by decision. Do not port unmounted `transcripts.py`, bulk/search/ask/recommendations routes excluded by `internal-api-endpoints.md`, or the SPA fallback under this plan. Do not expose provider-backed endpoints when required configuration is absent; no success stubs. Follow existing snake_case JSON except explicitly agreed compatibility changes.

| Workstream | Required, not mapped | Dependency / decision |
|---|---|---|
| Profile | `PATCH /api/profile/me`, `POST /api/profile/complete` | Database self-service security gate |
| Account admin | `POST /api/admin/users/{user_id}/deactivate`, `POST /api/admin/users/{user_id}/reactivate`, `DELETE /api/admin/users/{user_id}` | Auth/profile cross-provider reconciliation |
| Local admin | `GET /api/admin/ingestion/stats` | Simple local-staging-only metric; unavailable when staging is not configured |
| Uploads | `POST /api/files/upload`, `POST /api/videos/upload` | Admin-only; video slug/artifact contracts |
| Document admin | `DELETE /api/admin/documents/{doc_id}`, `PUT /api/admin/documents/{doc_id}/replace` | 404 on absent ID; preserve ID, report partial failures |
| Images | `GET /api/chat/content/images/{path:path}`, `GET /content/images/{path:path}` | Authenticated signed-URL issuance and client changes |

## Agreed product decisions (do not reopen implicitly)

- **Uploads and local-file ingest:** admin-only. Update `web/components/admin/upload.jsx`, `web/js/upload-single.js`, `web/js/upload-bulk.js` and any legacy clients to attach bearer tokens on multipart requests; do not preserve Python's public upload behavior.
- **Images:** issue short-lived signed Storage URLs to active, authenticated users; keep the bucket private. Both image aliases become authenticated URL resolvers returning `{url, expires_at}`; update image clients to fetch the resolver with a bearer token and set `<img src>` to the signed URL. This is an explicit change from Python's binary image GET; keep the alias paths but not their old unauthenticated/binary response. Assess document-level access if the knowledge base is not shared by all active users. Never place service-role credentials in URLs or logs.
- **Video:** preserve slug as document ID, create and store original, TXT/SRT/VTT and markdown summary artifacts. Use Azure Speech rather than simulate Whisper; accept only documented/translatable options (e.g. legacy default `model=small`, but reject other Whisper model values rather than ignoring them). Return real, short-lived signed artifact URLs in the legacy response keys, documenting expiration; UI must refresh expired links.
- **Replacement:** preserve the requested document ID; reject incompatible ID/type before deletion. **Delete:** missing document ID returns 404 (including repeat delete after complete removal). For partial multi-provider failures, return a sanitized non-2xx error and retain sufficient operation state for operator repair/retry; no false success.
- **Ingestion stats (interim simple choice):** retain the Python-style local directory scan *only* as a local staging metric. Label it as such in `web/components/admin/ingestion.jsx`; never call it cloud ingestion progress. If staging paths are absent/unconfigured, return a clear unavailable response (503), not misleading zero totals. Configured empty directories may return zero. Revisit a durable job metric later.
- **`POST /api/ingest/document`:** keep it, admin-only, restricted to a configured staging root.

## Preconditions shared by these routes

1. Apply the above authorization and client contract changes before mapping uploads/images. Python allows unauthenticated file/video uploads and image reads; `web/components/admin/upload.jsx` and upload utilities currently send multipart without bearer tokens. HTML `<img>` cannot attach bearer headers; callers must obtain signed URLs from the protected image resolvers. Test the chat renderer (`web/js/chat-utils.js`) and the legacy `/content/images/...` client. Do not make the admin group public to preserve legacy behavior.
2. Register `AddDocumentProcessing`, `AddVideoProcessing`, and `AddDocumentHandling` only with complete, validated dependencies/configuration (Speech endpoint/key, FFmpeg, LibreOffice as applicable, Supabase, Pinecone, embedding files). The API project already references them but `Program.cs` does **not** register them. Decide whether non-video ingestion can run without Speech: the current handler requires `IVideoProcessor` even for documents; split registrations/capabilities if separate availability is required. Bound multipart body and per-file sizes **before** expensive staging; cap concurrent CPU/FFmpeg/Speech jobs, enforce timeouts and cleanup on abort. Configure/document local staging permissions, request budgets, Storage bucket limits and accepted types (DocumentProcessor supports `.pdf`, `.docx`, `.doc`, `.txt`, `.md`, `.eml`; VideoProcessor has its own extension/size policy). Check magic bytes where feasible; never use client filenames as filesystem paths.
3. Treat `IDocumentHandler` as the ingest/delete owner; keep provider clients out of route handlers except read-only Storage delivery. Its ingest currently stages a file, writes chunks, vectors, then original Storage; rollback compensates chunks/vectors, but does not make an overwrite or a multi-provider failure atomic. Its delete removes vectors, chunks, then a Storage tree: failures after chunks are removed require explicit retry/reconciliation. Implement per-document serialization/locks and job idempotency for concurrent upload/replace/delete, including multiple instances. Record operation ID + stage and expose safe error text, not credentials, raw filenames/PII, paths or provider exceptions. A repeat destructive request must not claim success if cleanup cannot be verified.
4. For every route, add API fake-based contract/authorization tests and disposable non-production Supabase/Storage/Pinecone tests. Test missing provider configuration, inactive/deleted principals, invalid identifiers, partial provider failures and cancellation. Release gates include `dotnet/docs/plan/supabase-completion-remaining-plan.md` and UI smoke/contract comparison against the Python endpoints. Avoid returning 200 for partially completed destructive operations.

## Endpoint work

### 1. Self-profile writes (blocked by database gate)

- **`PATCH /api/profile/me`** — Current-user policy and caller's token/ID to `IUserProfileRepository.UpdateCurrentAsync`; accept only `full_name` and `avatar_url`, require at least one provided field, distinguish omitted from null according to an agreed contract, validate lengths/URL and reject privilege fields/unknown fields. Return the updated `ProfileResponse` shape (`id`, `email`, `full_name`, `avatar_url`, `role`, `status`, `created_at`); return 404 if profile no longer exists/visible, never allow changing identity/role/status. Tests: allowed edit, empty/unknown/mixed privileged input, other-user ID spoofing, missing/disabled profile, caller-token RLS, cancellation. **Do not map until** `dotnet/docs/plan/supabase-profile-self-service-security.md` has an applied, reviewed ACL/RLS/signup migration and direct PostgREST negative tests (including anon and mixed protected-field updates). The .NET DTO is not a security boundary against direct Supabase clients.
- **`POST /api/profile/complete`** — Alias of the same validated write logic and response; do not silently create a profile or bypass the security gate. Verify signup profile creation is functional and safe before exposing. Test response/validation equivalence to PATCH, including first-login and already-complete cases; neither path may bypass the current-user policy.

### 2. Admin account lifecycle

All three use the existing `/api/admin` admin policy, validate GUID target IDs, read the target via `IAdminProfileRepository.GetByIdAsync`, and block self-target and superuser-target actions. `IAdminProfileRepository.UpdateAccountStateAsync` enforces **no** lifecycle policy; implement it in the API/application workflow. `IAdminIdentityGateway` is privileged; keep its results and errors sanitized. Choose a durable audit/reconciliation method before enabling these operations, since Supabase Auth and profile updates cannot share a transaction. Re-read/conditionally update state to guard concurrent admins and status changes (add a conditional repository method if necessary).

- **`POST /api/admin/users/{user_id}/deactivate`** — Optional `{reason}` request; bound/sanitize reason and keep it out of ordinary logs if sensitive. Reject absent, inactive or deleted target. Retrieve Auth email if required for the legacy response; decide whether missing Auth account is conflict vs recoverable partial failure, not `"unknown"` success. Ban via `SetBannedAsync(id, true)`, revoke sessions via `RevokeSessionsAsync`, then set profile `status=inactive`, `deleted_at=UTC now`, `deleted_by=admin ID`. JWT revocation alone may not immediately invalidate existing access tokens; current-user profile check must block them. Choose/report policy for any Auth failure: no silent Python-style continue-and-success. Preserve response keys `message`, `user_id`, `email`, `status`, `deleted_at`. Test failure at each step and retry from each partial state; make deactivation safe to resume.
- **`POST /api/admin/users/{user_id}/reactivate`** — Only inactive targets, never deleted; validate Auth user exists, unban via `SetBannedAsync(id, false)` and restore profile `status=active`, `deleted_at=null`, `deleted_by=null` (legacy `restored_at` UTC response). Carefully sequence to avoid leaving a profile active while Auth remains banned, or Auth enabled while profile is inactive; report/reconcile either partial outcome. Test already-active/deleted, Auth missing, unban failure, profile failure and retry. Do not accidentally interpret a soft-deleted profile as a deactivation.
- **`DELETE /api/admin/users/{user_id}`** — Irreversible: verify target role/state and identity/email, delete invitations by email via `IInvitationRepository.DeleteByEmailAsync`, then `IAdminIdentityGateway.DeleteUserAsync`. Check actual Auth → profile/session/message FK cascades and invitation/feedback `SET NULL` behavior in a disposable project, rather than relying on Python's comments. Decide whether invitation deletion failure blocks Auth deletion and how to reconcile a succeeded invitation deletion followed by failed Auth deletion. Return `message`, `user_id`, `email`, `permanently_deleted: true` **only** after confirmed deletion; prevent races with other admin changes. Tests: no target, self/superuser, Auth not found, invitation failure, Auth failure, retry after partial deletion, and real cascade verification.

### 3. Local admin ingestion status

- **`GET /api/admin/ingestion/stats`** — Admin policy; Python `app/api/endpoints/admin/ingestion.py` recursively scans `DOCUMENTS_DIR` for `.pdf/.doc/.docx/.txt/.md`, compares filename stems to subdirectories of `PROCESSED_DIR/content_repository`, and returns `{total_documents, processing:0, completed, documents:[{name,size,status}]}` with `pending`/`ingested`. Implement a bounded read-only scanner with configured paths, safe missing-dir semantics, IO error behavior, deterministic ordering and no path leakage. This is **not** a Pinecone/Supabase completion metric; current .NET ingest stages in temp and deletes that staging file, so Python's rule may always return empty or stale results. For now use configured local staging/processed directories and a bounded legacy-compatible scan; mark the UI (`web/components/admin/ingestion.jsx`) explicitly as **local staging**, not cloud ingestion progress. Return 503 if paths are not configured or no longer exist, with a safe error response; return zero only when configured directories exist and contain no matching documents. Document that uploads handled directly by .NET do not necessarily appear here; a durable job-status metric is future work. Test extension filtering, recursive files, duplicate stems, missing/denied directories, scan limits and UI interpretation.

### 4. Uploads

- **`POST /api/files/upload`** — Multipart `file`, one item. Require the admin policy (see agreed decisions). Validate nonempty file, supported extension/type, sanitized basename, size and storage quota; feed stream to `IDocumentHandler.IngestAsync(new DocumentHandlerInput(...))` under concurrency limits and cancellation. Python replies `{message, supabase, ingestion}` even when ingestion fails, and mirrors original to Storage best-effort; .NET handler instead treats original Storage failure as failure and returns `{documentId, sourceName, sourceType, chunkCount, vectorCount, sourceObject}` on success. Agree on an explicit mapping or versioned divergence: do **not** fabricate `stored:true` or turn failed ingestion into 200. Verify legacy single/bulk upload client expectations (`web/js/upload-single.js`, `upload-bulk.js`), video-by-extension behavior, `.eml`, MIME and 50 MiB document vs 500 MiB handler/video limits. Tests: empty/oversized/unsupported, unauthenticated/inactive, duplicate ID/overwrite, processor failure, chunk/vector/original failure and rollback, downloadability after success.
- **`POST /api/videos/upload`** — Multipart `slug`, `file`, optional `model` (Python default `small`) and `language`. Validate slug grammar/length, extension, size and duplicates. Current VideoProcessor uses Azure Speech/FFmpeg and derives `DocumentId` from **filename**, not form slug; `IDocumentHandler.IngestAsync` does not accept explicit ID or language/model. Extend the handler/processor contracts to use the validated slug as a stable ID independent of the filename, and map supported `language` to Azure Speech locale settings or return 400 for unsupported values; accept the legacy default `model=small` as a compatibility no-op and reject other Whisper model choices. Python returns `{ok,slug,original_video_url,transcripts:{txt,srt,vtt},summary_md}`; current `VideoProcessingResult` exposes sections/chunks but handler stores only original/chunks/vectors, not TXT/SRT/VTT/summary artifacts. Extend contracts, artifact generation and Storage keys to save all five artifacts (original plus TXT/SRT/VTT/summary); return real short-lived signed URLs in the legacy keys and document expiration/refresh in UI. Do not return placeholder URLs from `GetPublicUrl`, and do not make the bucket public. Test FFmpeg/Speech failure/timeouts, slug vs filename identity, timestamps/artifact content, storage limits/ACLs, partial artifact cleanup, successful retrieval and admin upload UI (`web/components/admin/upload.jsx`).

### 5. Admin document lifecycle

- **`DELETE /api/admin/documents/{doc_id}`** — Validate ID using the same rules as existing download, admin policy, call `IDocumentHandler.DeleteAsync`; return 404 for `Found=false` (including repeated deletes after full removal) and pin it in tests. On true success return Python-compatible `{success:true,message}`. Never copy Python `_purge_document`'s swallow-and-success behavior. Test Pinecone, chunk DB and Storage failures individually, absent ID, repeat deletion, cleanup of original/images/video artifacts, and retries when the DB metadata was already removed (the handler searches both Storage areas when metadata is absent). Track/orchestrate cleanup of orphan vectors if chunk IDs have already disappeared; no response may falsely claim all stores cleared.
- **`PUT /api/admin/documents/{doc_id}/replace`** — Validate target exists via `IChunkRepository.GetDocumentMetadataAsync`, admin policy, multipart `file`, same upload constraints. Python writes a local file, purges then calls the ingest endpoint (which derives the new ID from filename): it does **not** guarantee ID preservation. Extend the handler with a stable-ID/source-name replacement operation (or validate an exact ID match for a simpler first version); always preserve the requested ID and reject incompatible source type/file before deleting anything. Define same-key original overwrite and video support explicitly in tests; do not silently change ID or source type. Prefer stage/process new content before destructive delete; otherwise add a durable per-document recovery record and return an explicit partial-failure error if delete succeeded but ingest failed. Never call the HTTP upload handler internally. Success `{success:true,message,ingestion:...}` only after all providers succeed; test missing doc, ID/type mismatch, validation before delete, failure at each delete/ingest stage, concurrent replace vs delete/upload, unchanged downloadable original on failed replace where promised.

### 6. Image-serving compatibility aliases

- **`GET /api/chat/content/images/{path:path}`** and **`GET /content/images/{path:path}`** — Map both to one current-user-protected signed-URL resolver; they return `{url, expires_at}` for a validated private Storage object (not bytes), and return 404 when missing. Python streams `docs/{doc_id}/images/{filename}` from documents Storage and supports legacy `images/{filename}` via local lookup; the current .NET DocumentProcessor/Handler does not persist extracted image objects or `ImagePaths` in its chunk writes. Inventory actual images/citations, add missing processing + private Storage upload/deletion for new documents, and migrate legacy local assets or return explicit 404 for those not migrated. Do not silently promise all old images will work. Accept only canonical, strictly decoded `docs/<validated-id>/images/<safe-name>` (and an explicitly scoped legacy resolver if needed); block traversal, encoded separators/double decoding, control chars and arbitrary Storage keys. Verify object presence with an appropriately scoped Storage lookup (or a focused `ExistsAsync` contract), then `IObjectStorage.CreateSignedUrlAsync` with short TTL; do not issue links for arbitrary Storage paths or leak signed URLs in logs. Limit image types; exclude SVG unless sanitized/policy-approved. Resolver responses should be `Cache-Control: no-store`; test link expiry and refresh, both aliases, modern/legacy paths, path attacks, private bucket, missing files, inactive/anonymous callers and chat image rendering through the client signed-link flow.

## Retained operator route

- **`POST /api/ingest/document`** — Mounted in Python but hidden and now explicitly retained as an admin-only operator route. Accept only a validated filename under a configured staging root (real-path containment, symlink/traversal protections), call `IDocumentHandler.IngestAsync`, return a documented `IngestResponse` mapping and test unknown files, malformed paths and provider failures. If the staging root is absent, return a clear unavailable error rather than searching arbitrary filesystem paths. Do not expose Python's local filesystem read to unauthenticated callers. `POST /api/ingest/bulk` remains out of scope.

## Delivery and acceptance sequence

1. Implement the agreed upload/image authorization and client changes, local-staging-only label, video artifact/model/slug contract, preserved replacement identity, 404 delete policy and admin operator route. Record Python-to-.NET response/status divergences (including signed image resolver JSON vs binary, signed video URL expiration, and 400 vs 422) in contract tests.
2. Finish non-production Supabase profile ACL/RLS/signup security and Auth/Storage/FK checks. Then add profile writes and admin lifecycle with race, permission and partial-state tests. Do not enable self-profile writes while that gate is open.
3. Register processor/handler dependencies and limits; build upload + delete flows with disposable provider fault injection, verified original download, key layout and resumable repair. Implement replace only after ID/overwrite and recovery policies are demonstrated.
4. Build video artifact/slug handling and private image persistence/signed-link access, then the local staging stats scanner; compare all 13 retained method/path contracts with Python while asserting agreed divergences, and exercise admin/chat UI paths including authenticated multipart, expired links and image display.
5. Route traffic only after security-owner approval, deployment-specific configuration/permissions, backpressure/load tests, and proven operator repair procedures for failed multi-provider writes. Until then retain Python routing for missing paths; do not use a green .NET unit-test run as a cutover signal.
