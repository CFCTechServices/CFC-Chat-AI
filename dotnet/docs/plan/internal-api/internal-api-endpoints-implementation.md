# Internal API migration: implementation status and cutover gates

This records the work applied against `docs/plan/internal-api-endpoints.md`. **This is not a completed migration or approval to switch traffic from Python.** Unlisted routes have not been mapped; there are no success stubs.

## Implemented

- `CFC.ChatAI.Api` references the provider/application projects. When *all* Supabase URL, anon key, and service key settings are present, it registers the Supabase adapters, current-user authentication (Auth token validation + caller-token/RLS profile read on each request), an active/not-deleted policy and an admin/superuser policy. Admin groups require the latter. Service-role credentials are never serialized into auth/config. Without complete Supabase configuration the provider-backed routes are not mapped; health remains available.
- Public: `GET /api/auth/config`, `POST /api/auth/check-email`, `POST /api/auth/forgot-password`. Password recovery uses the anon key, generic non-enumerating replies and a typed provider 429. Both public POSTs have per-IP fixed-window limiting (10 requests/5 minutes). Verify Auth-project recovery settings and configure `FRONTEND_BASE_URL` before use.
- User: `GET /api/profile/me`; `GET/POST /api/chat/sessions`, `GET/PATCH/DELETE /api/chat/sessions/{sessionId}`, `GET /api/chat/feedback`. Session reads and mutations use the **caller token and ID**, not service credentials. Lists aggregate bounded pages up to a ceiling; exceeding it returns 413 instead of a silently incomplete array. A session deletion that has already removed messages but cannot remove the session returns an explicit partial-failure 500.
- When `PINECONE_API_KEY`, `PINECONE_INDEX_NAME`, `Embedding:ModelPath`, and `Embedding:VocabularyPath` are also configured: `POST /api/chat/message`, `POST /api/chat/feedback`, and `GET /api/visibility/vector-store`. Vector stats deliberately require a current user (Python exposed them publicly). Vector stats cannot report index fullness from the existing stats contract and currently return `null`. Chat sends through `IChatService`; feedback vote uses the atomic RPC and the owned assistant context, then **synchronously** replaces query events with the same query embedding model as retrieval, without running a search. This differs from Python background processing: an event failure reports a partial 500, and re-submitting the same rating retries the event replacement. Multi-instance ordering and durable retries still need design and tests; do not ship feedback at scale without them.
- Admin: `POST /api/admin/invite`, `GET /api/admin/invitations/status/{email}`, `GET /api/admin/users`, `POST /api/admin/change-role`, `GET /api/admin/documents`, `GET /api/admin/documents/{docId}/download` (five-minute signed original URL), and `GET/PATCH /api/admin/settings` (validated, serialized local file with atomic rename and safe corrupt-file reads). Existing-account, pending-invite, expired reinvite, race conflict, self-role and superuser protections are enforced. Invitation creation is a whitelist insert, **not** an email send. If deletion of an expired invite succeeds and insert fails, retry/reconcile the email in the invitations table; this is not transactional. Admin lists have the same 413 ceiling; document summaries currently scan chunk pages in the repository.
- Health retains the host-only `/api/health` shape. Detailed health's Supabase probe now uses `ISupabaseHealthGateway` (service credentials stay in Supabase); the existing Pinecone **control-plane** probe is unchanged, not silently replaced with a data-plane query. Public health errors no longer include caught exception messages. Status/timeout handling remains bounded.
- Host error mapping sanitizes dependency failures (503), other failures (500), and partial session deletion (500); no tokens or provider exception messages are sent to clients. Authentication tests verify inactive profiles are denied, users cannot access admin routes, and session ownership calls carry the caller's token. Run `dotnet test dotnet/CFC.ChatAI.slnx`.

## Still required before routing cutover

1. **Security/integration gates:** test caller-token RLS and Auth recovery against a disposable Supabase project; verify profile creation/status/deletion rules, grants, Storage buckets, feedback RPC, and partial failure behavior in `docs/plan/supabase-completion-remaining-plan.md`. Profile writes (`PATCH /api/profile/me`, `POST /api/profile/complete`) are **intentionally not mapped** until the database security work in `docs/plan/supabase-profile-self-service-security.md` is proven. Configure trusted proxy forwarding before relying on the per-IP rate limiter; add per-email limiting and request/time budgets. Admin role changes need concurrency/transition testing.
2. **Admin/local operations not yet implemented:** user deactivate/reactivate/delete, ingestion filesystem statistics. The settings file is local to one host (`Api:AdminSettingsPath`); shared persistence/locking across instances is needed for multi-instance deployment. Corrupt settings read with defaults but writes fail until the file is repaired. Account and invitation changes need tested cross-provider partial-failure policies. Pagination above the current cap requires an agreed contract; do not pretend lists are complete beyond it.
3. **Content routes not yet implemented:** files/video upload, admin document delete/replace, both image aliases, optional admin-only local ingest. Download URL/key behavior still requires disposable Storage tests. Validate size/type/key/path/permissions and original/artifact parity, configure processors through DocumentHandler, and test failures between Storage, chunks and Pinecone operations before enabling writes. Never copy Python's error-swallowing delete behavior.
4. **Feedback:** move event replacement to a durable, ordered worker if asynchronous parity/latency is needed. Verify idempotent vote retry, event cleanup on clear, image/citation metadata, session-size batching, and failures after user-message persistence. Provider-backed contract tests and UI smoke tests for **every** retained route remain outstanding.
5. **Other deviations:** HTTP validation currently returns 400 (rather than Pydantic's 422), responses use the configured snake_case serializer except legacy camelCase auth/config, detailed session preview is repository-provided, vector stats are protected, and unavailable provider-backed routes are absent (404), not placeholder successes. The optional/out-of-scope endpoints listed in the original plan have not been mounted.

Keep Python routing for outstanding endpoints. Do not switch all traffic to .NET on the basis of the passing unit tests alone.
