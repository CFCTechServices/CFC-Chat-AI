# Remaining internal API endpoints — development delivery

This record describes the first six of the eight method/path pairs. The final two profile write routes were subsequently implemented behind `Api:EnableProfileWrites` (default off); enabled-route tests and the [database security gate](../../plan/supabase-profile-self-service-security.md) remain outstanding. No database migration, live provider acceptance or browser cutover is implied. Video remains out of scope. See the current [cutover checklist](../../plan/internal-api-cutover.md).

## Configuration and contracts

| Route | Requirements and deliberate differences from Python |
|---|---|
| `GET /api/admin/ingestion/stats` | Admin; set `Document__StagingRoot` and `Document__ProcessedRoot` to existing, absolute local paths. The processed root must contain `content_repository`. Scans up to 10,000 entries across both roots and 32 directory levels; missing, unreadable or over-limit scans return 503, not zero. Counts `.pdf/.doc/.docx/.txt/.md` files recursively, matching basename stems case-sensitively against immediate processed directories. Duplicate stems count as separate files. `processing` is always zero. The stats tab remains unmounted; its labels and 503 handling describe local staging, not cloud progress. |
| `POST /api/ingest/document` | Admin and configured document providers; body is `{"filename":"example.docx"}`. Reads one file in the root, never searches subdirectories and never follows symlinks/junctions. 404 for a missing file, 503 for unavailable staging, 409 for an existing ID. Uses upload file extensions (including `.eml`) and `Document__MaxUploadBytes`; the source file stays in staging. The response is `{success,message,chunks_processed,sections_processed,images_processed,doc_id,source,vector_count}`. `source` is a filename, never a server path. |
| `PUT /api/admin/documents/{doc_id}/replace` | Admin and configured document providers. Send `multipart/form-data` with one `file`; its filename must derive the exact ID and use the existing extension (case-insensitive). Only known `document` metadata is eligible. Missing target → 404; ID/type/format conflict → 409. Success is `{success:true,message,ingestion:…}` with the staged-ingest response shape. Content Library requires confirmation and shows partial-failure references. |
| `POST /api/admin/users/{user_id}/deactivate` | Admin, lifecycle opt-in (`Api__EnableAccountLifecycle=true`), and `Api__AccountLifecycleJournalDirectory`. Requires an active target and matching Auth ID/email. Optional `reason` is restricted to 500 characters without controls; it is not retained. Ban, revoke sessions, then conditionally mark the profile inactive. Returns `message,user_id,email,status,deleted_at`. |
| `POST /api/admin/users/{user_id}/reactivate` | Same lifecycle opt-in. Only `status=inactive` is reversible, including older deactivation rows with `deleted_at`. `status=deleted` is not reversible. Unban Auth before conditionally restoring the profile. Returns `message,user_id,email,status,restored_at`. |
| `DELETE /api/admin/users/{user_id}` | Requires lifecycle opt-in **and** `Api__EnablePermanentAccountDeletion=true`. Active or inactive targets only. Invitation deletion by verified Auth email must succeed before Auth deletion. Returns `message,user_id,email,permanently_deleted:true` only after Auth and profile absence are confirmed. The active account UI checks that response and surfaces reconciliation references rather than treating an ambiguous response as success. |

All account mutations reject self-targets and superusers. Feature flags default off; authorized callers receive 503 for disabled account actions. Supabase-backed endpoints are not mapped without Supabase settings; staged ingest and replacement additionally require Pinecone and embedding configuration. Use storage and directory ACLs: staging roots, their ancestors and staged entries must be under trusted operator control. Publish only regular files, preferably by atomic rename. Never grant filesystem write access to API callers or point these settings at a general upload directory. Link checks are not a sandbox against concurrent changes by a privileged local process.

## Reconciliation

**Replacement:** New content is staged and processed before any old provider writes. Purge removes old vectors, images, obsolete Storage artifacts and chunk rows, but preserves the canonical original key. Publication writes images, chunks and vectors, then overwrites that original key last. If the original write is never attempted, the canonical original remains; a lost overwrite response can leave either version. Legacy originals at other keys are not protected. A post-purge-start failure is non-2xx with `stage` (`purge` or `publish`) and a `reference`. A canceled request may not deliver a response; inspect server logs. Chunk/vector/image compensation is best-effort, not a rollback of the old document. Before retrying, stop writes for that ID and independently inspect Supabase rows, Pinecone IDs and the Storage tree. If in doubt, reconcile orphaned data using the [delete recovery notes](../../complete/document-deletion/document-deletion-changes.md) and reingest from backup. A metadata 404 is not proof of cleanup. Document mutations share an API-process-only exclusion slot; multiple replicas, Python, tools and direct provider edits are not fenced. There is no durable document recovery record.

**Accounts:** Before enablement, inspect the actual target with [`inspect-account-and-profile.sql`](sql/inspect-account-and-profile.sql), resolve the profile ACL risk, and review/apply [`revoke-banned-user-sessions.sql`](sql/revoke-banned-user-sessions.sql) in a disposable project. GoTrue's `/logout` requires the target JWT; the service-role RPC follows GoTrue's session deletion behavior for a banned target. Verify the session/refresh-token FKs, function ownership and effective grants. The exported schema does not establish any hard-delete cascades. Do not enable hard deletion until those tests pass.

Pre-create a dedicated persistent journal directory, writable only by the API service account and trusted operators; do not put it under staging, in the repo or in a public log sink. It contains account IDs and email: restrict access, back it up securely and apply your retention policy. The journal records intent before provider writes, records permanent-delete intent after confirmed invitation cleanup, and renames completed records to audit receipts. Run a single writer .NET host for the account workflow. Do not run Python, other replicas or direct admin writes for the same accounts while using it. Same-target lifecycle and role changes are serialized within that host; profile changes use a compare-and-set against role/state/deletion metadata. This is not a distributed transaction or a fence against provider-side writes.

For a pending record, retry **the same action** once dependencies are healthy; a different action and role changes are blocked. If the previous response was lost after confirmation, repeat calls may return a state conflict or 404; use the journal and provider checks rather than assume an unsuccessful previous action. Deactivation can leave Auth banned while the profile is still active until the operation is resumed; do not infer immediate invalidation of every JWT. Reactivation can leave Auth unbanned with an inactive profile; the current-user check still denies application access. If profile, role or email no longer matches the pending snapshot, or Auth is missing while the profile remains, stop and reconcile manually. Use the response reference to find the journal record; verify the Auth user, ban, sessions, profile and invitations before rearming or archiving a pending operation. Do not delete a pending record simply to clear a UI error.

## Disposable acceptance tests (not run in this change)

1. Use an isolated Supabase project/private Storage bucket and Pinecone index/namespace. Point a loopback .NET host at those providers, set staging paths, and create a separate admin and normal user. Set their tokens in `SMOKE_ADMIN_TOKEN` and `SMOKE_USER_TOKEN`. From the repo root run `python tools/smoke_remaining_internal_api.py --confirm-disposable --staging-root <absolute-path>`. This writes, replaces and deletes a unique test document; if it stops mid-run, its printed ID identifies the fixture to reconcile. Separately compare Supabase chunk rows, Storage originals/images and Pinecone vectors before and after replacement/deletion (record old chunk IDs and check old-only IDs independently of metadata).
2. Before enabling lifecycle on the disposable host, run the catalog inspection and the [profile security checklist](../../plan/supabase-profile-self-service-security.md). Apply the reviewed revocation RPC. Test the RPC is denied to anon/authenticated, rejects an unbanned account under service role, and removes only the banned test user's sessions and refresh tokens. Confirm a saved refresh token cannot mint a session after deactivation; a fresh login works after reactivation. Run the smoke command with `--account-target <disposable-user-uuid>` and `SMOKE_ACCOUNT_TARGET_TOKEN` for that separate user. Confirm any still-valid JWT cannot access the .NET API during deactivation.
3. For hard deletion, seed target-owned chat sessions/messages, invitations (target email and separate `created_by`/`used_by` references), feedback linked to the target and to target-owned messages, `deleted_by` references and chunk feedback events. Inspect actual FK actions and agree on what is deleted vs anonymized; do not assume a nullable field means `SET NULL`. Only after verifying the expected behavior, enable the disposable hard-delete flag and run with `--delete-account-target`. Query each table afterward; the API smoke check only establishes the HTTP result and profile absence. On a disposable target, interrupt each provider write (including a lost response) to verify errors, pending records and same-action resume. Repeat cancellation checks before and during destructive operations.
4. Host the UI separately with same-origin routing to the correct backend. Browser-smoke authenticated upload/download/replacement/delete, account errors, and private DOCX images in new and reopened chats; test signed URL expiry and deletion. Leave local stats unmounted unless needed; if mounted, verify 503 isn't shown as zero. Use the intended legacy routing or disable profile edits while gated; the .NET host does not serve the SPA. Do not proxy dev ingest/delete routes.

The local suite exercises authorization, identifier/filename validation, bounded staging, contract shapes, cancellation, same-host conflicts, provider failure injection, replacement original handling, and lifecycle journal retries. It does not substitute for these acceptance checks or close the Supabase or release gates.
